# Documentación de producto — GoldenWeb 2.0

Documentos de planeación (visión, requerimientos, backlog, arquitectura,
modelo de datos), generados y mantenidos en la sesión de Claude dedicada a
producto/documentación. El detalle técnico vivo del código está en
`CLAUDE.md`, en la raíz del repo, y lo mantiene la sesión de Claude Code.

| Documento | Contenido |
|---|---|
| [`00_REQUERIMIENTOS_ROADMAP.md`](./00_REQUERIMIENTOS_ROADMAP.md) | Contexto de negocio, flujo del sistema legado, backlog de requerimientos nuevos por módulo, preguntas abiertas, roadmap por fases |
| [`01_VISION_Y_ALCANCE.md`](./01_VISION_Y_ALCANCE.md) | Visión, objetivos de negocio, alcance dentro/fuera, stakeholders, criterios de éxito |
| [`02_CLASIFICACION_FURPS.md`](./02_CLASIFICACION_FURPS.md) | Plantilla de clasificación FURPS+ y los requerimientos nuevos clasificados (categoría, prioridad MoSCoW, complejidad, dependencias) |
| [`03_PRODUCT_BACKLOG.md`](./03_PRODUCT_BACKLOG.md) | Backlog en formato Scrum: épicos, historias de usuario con criterios de aceptación, Definition of Ready/Done |
| [`04_ARQUITECTURA.md`](./04_ARQUITECTURA.md) | Stack, decisiones de arquitectura (ADR), estructura objetivo de monorepo, vista de despliegue |
| [`05_MODELO_DATOS.md`](./05_MODELO_DATOS.md) | Modelo de datos actual (ER) y extensiones conceptuales por módulo futuro |
| [`06_BRIEF_SPRINT_1.md`](./06_BRIEF_SPRINT_1.md) | Brief listo para pegar en la sesión de código al empezar el siguiente sprint |

Este conjunto se actualiza desde la sesión de producto a medida que cambian
prioridades o aparecen nuevos hallazgos — si algo aquí no coincide con lo que
hay implementado, manda el código (y `CLAUDE.md`), no estos documentos.
